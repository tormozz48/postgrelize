# v6 baseline causes (2026-11-25)

Every entry of `scripts/v6-suite/baseline.json` (691 entries: failing tests and files that do not load, v6.37.8, PostgreSQL 17) now has a cause. Spec: `.10x/specs/2026-11-22-v6-compat-gate-design.md` (gate 1, G5). Format: `scripts/v6-suite/README.md`, section Causes.

## Method

Unit and integration run with `npm run v6:suite` on a private PostgreSQL (:54398), 4 workers, plus an `--update-baseline` run of each kind (two runs each) that regenerated the lists. Failures were grouped by root cause from the first error line, the v6 test source and the postgrelize code. Each `bug` has a minimal reproduction against `dist/index.cjs` that was checked against v6's behaviour (v6 source or real sequelize@6); the four `data-loss` bugs were reproduced again by hand when writing this report. Failures were assigned to causes by rules (file, title, message) written per slice; a catch-all per file marks the rest `triage`. Not reproduced: unit `sql/*` and `query-interface/*` were only skimmed (they are `queryGenerator` internals), PostGIS tests need a PostGIS image, and files that crash mid-run on an unhandled rejection (`model/findOne`, unit `instance/*`) hide further failures that no run shows.

The baseline of main listed 661 entries but was stale: 5 integration regressions (query bind tests, one json placeholder test) were not reproducible in the regenerating run, and `unit/sql/json.test.js` loads now with 28 failures. The regenerated lists replace the old ones; the numbers are state of main at 1.9.3.

Suggested PRs, in order:

1. **Scope and increment data loss** (`scope`, `model`): `Model.increment`/`decrement` without `where` and through `Model.scope(..)`; `hasOne`/`hasMany` `set` ignoring the association `scope`.
2. **Association getters/setters** (`associations`): `scope` option of getters, default scope in `set`/`add`, `get(instances, {limit})`, paired `belongsToMany` keys.
3. **Include** (`include`): scope merge, `limit` without `separate`, nested `separate` order, option propagation.
4. **Instance/model writes** (`instance`, `model`, `upsert`): `update` dirty fields, nested JSON `set`, hook re-validation, composite unique upsert target.
5. **Datatypes** (`datatypes`): `DataTypes.X` instanceof, options-object constructors, DATE from number.
6. **Query/query-interface/ddl**: `createTable` schema/`uniqueKeys`, `changeColumn` references, bind `$$`, `SHOW`, pool reuse of ended connections.
7. **Error constructors, wording, config**: constructors without arguments, message text.

Each PR deletes the entries it fixes from the baseline (`stale` shows them) and the matching `bug` causes.
